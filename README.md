# Music & Podcast Database - SQL Server

Relational database project for a digital music and podcast store built in SQL Server/T-SQL, including 3NF normalization, primary and foreign keys, data inserts, views, stored procedures, functions, triggers, automation logic, and validation queries.

> Status: Completed academic database project — fully documented and uploaded.

## 🎯 Project purpose

The purpose of this project is to manage the resources of a digital music and podcast store in an organized and efficient way. The database supports the storage, consultation, and management of information related to users, available content, artists, podcasts, purchases, ratings, favorites, and sales activity.

## 📌 Main requirements

- Register and authenticate users with assigned roles.
- Store information about songs, albums, podcasts, and episodes.
- Associate content with artists and content creators.
- Manage musical genres and thematic categories.
- Register user purchases and purchase details.
- Allow users to rate and comment on content.
- Allow users to mark content as favorite.
- Support searches by title, artist, genre, duration, or content type.
- Generate activity and sales reports.

## 🛠️ Technical scope

- SQL Server database design
- Relational model
- Normalization up to 3NF
- Primary keys and foreign keys
- Data insertion scripts
- Views
- Stored procedures
- Functions
- Triggers
- Automation logic
- Validation queries

## 📂 Repository structure

```txt
sql/
docs/
diagrams/
screenshots/
```

- `sql/`: SQL Server scripts for database creation, inserts, views, procedures, functions, triggers, and validation queries.
- `docs/`: project documentation, requirements, normalization notes, and technical explanations.
- `diagrams/`: relational model and database diagrams.
- `screenshots/`: evidence of database execution and query results.

## ▶️ How to run

1. Open SQL Server Management Studio.
2. Create or connect to a SQL Server instance.
3. Run the scripts inside the `sql/` folder in order.
4. Execute the validation queries to verify tables, relationships, views, procedures, functions, and triggers.

## 📚 Project context

This project was developed as an academic database design project. Its main goal was to apply relational database principles in a practical case, including data modeling, normalization, referential integrity, automation through database objects, and query-based validation.
